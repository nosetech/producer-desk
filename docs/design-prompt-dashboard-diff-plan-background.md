## ここからプロンプト

既存のproducer-deskダッシュボードの「AIに計画してもらう」を、**依頼を投入するだけでバックグラウンド処理される方式**に変更します。あわせて、**inbox一覧上で計画の状態表示・内容確認**ができるようにしてください。既存の配色・トーン・アイコンは維持してください。

### 背景

計画の生成はオーケストレータ側のキューで実行され、依頼後はパネルを閉じても、リロードしても、結果は失われません。完了・失敗はSlackに通知されます。計画ジョブは承認（issue登録）または破棄されるまで保持されます。

### 追加・変更する内容

1. **依頼後の挙動（コンポーザー）**: 「計画を依頼」ボタン（旧「計画を作成」）を押すと投入だけして直ちにパネルを閉じられる。「依頼しました。完了するとSlackに通知します」という控えめなトーストを出す。新規タスク由来の計画は、新規作成UIを開いたときに未承認の計画（キュー待ち／計画中／確認待ち／失敗）を一覧で復元表示し、選んで確認できる導線にする。
2. **inbox一覧の計画状態バッジ**: inbox項目の行（カード）に、計画の状態バッジ「キュー待ち（◯番目）」「計画中」「確認待ち」「失敗（種別: 解釈不可／タイムアウト／利用リミット／失敗）」を表示。計画がない項目にはバッジを出さず、既存の「AIに計画してもらう」ボタンを維持。計画中・キュー待ちは既存の進捗表示（スピナー）のトーンに合わせる。
3. **inbox項目からの計画内容の確認**: 「確認待ち」「失敗」の項目から「計画を開く」で、既存の計画確認ステップと同じ見た目のパネル（インライン展開またはサイドパネル）を開く。タイトル・本文の直接編集、「AIに修正を指示」（修正もバックグラウンドで実行、実行中は直前の計画を残してバッジを「計画中」にする）、「承認して登録」（承認でinbox項目が`status:todo`へ昇格）、「破棄」、失敗時の「再試行」。
4. **失敗表示**: 失敗種別つきのインラインエラーと「再試行」ボタン。再起動で中断されたジョブも同じ失敗表示（種別「中断」）。
5. **状態**: 計画なし／キュー待ち／計画中／確認待ち／失敗／修正中（直前の計画を表示したまま実行中）／読み取り専用で操作不可。
6. **PC幅・モバイル幅**、**ライト・ダーク両方**。

### 成果物として欲しいもの

1. inbox一覧（各状態のバッジが並んだ状態）
2. 計画を開いた確認パネル（確認待ち・修正中・失敗）
3. コンポーザー依頼直後のトーストと、新規タスク由来の未承認計画の復元表示
4. モバイル幅とダークモードでの見た目

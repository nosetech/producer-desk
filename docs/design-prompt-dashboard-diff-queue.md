# Claude Designへの追加指示プロンプト: プロジェクトチップへのディスパッチキュー表示の追加（差分）

[design-prompt-dashboard.md](./design-prompt-dashboard.md)でお願いしたダッシュボードデザインに対する**追加の変更依頼**です（[design-prompt-dashboard-diff-status-counts.md](./design-prompt-dashboard-diff-status-counts.md)の適用後を前提とします）。既に作成済みのモックアップがある場合は、それを更新する形で対応してください。ゼロから作り直す必要はありません。以下を丸ごとコピーし、既存デザインを作成したClaudeとのやり取りに貼り付けてください。

## ここからプロンプト

前回お願いしたproducer-deskダッシュボードのデザインについて、「プロジェクトの並行状況」ウィジェットの**各プロジェクトチップに、そのプロジェクトのAI実行キュー（待ち行列）の状態を絵で表示するミニ図**を追加してください。他の要素のデザイン・レイアウトはそのまま維持してください。

### 背景

AIエージェントは1プロジェクトにつき同時に1つのタスクしか実行せず、実行中に届いた指示は先入れ先出し（FIFO）の待ち行列に積まれます。現状、プロジェクト全体で「いま何が実行中で、何件が待っているか」を俯瞰する手段がありません。

### 追加するミニ図の仕様

- 各プロジェクトチップの中に、「キュー（待ち行列の枠）」を表す小さなレーンを置く。レーンの中に、**実行中のタスク1つ**と**待機中のタスク**を、タスク1件につき1つのアイコン（丸・角丸四角など）で並べる
- **通常表示では文字を出さない**。ただし待機が多い場合（目安: 5件超）は、先頭から数件のアイコン＋ `+N` で省略する
- 実行中タスクはレーンの**先頭（左端）**に置き、動きのある表現にする（例: 脈動・回転・流れるハイライト）。待機中タスクはその右にFIFOの順に並べ、静的で控えめな見た目にする。実行中と待機中は色・形・アニメーションで一目で区別できること（`prefers-reduced-motion`ではアニメーションを止め、形・色だけで区別できるようにする）
- キューが空（実行中も待機も無い）のときは、空のレーン枠のみ（またはごく控えめな表示）にする。チップの高さ・レイアウトが、キューの有無や件数で崩れたり大きく変わったりしないこと
- 同じissueへの指示が複数積まれることがあるため、同じissueのアイコンが複数並ぶことがある（重複はそのまま並べてよい）

### ホバー／フォーカス／タップ時のツールチップ

- 各タスクのアイコンに**マウスオーバー**すると、そのタスクに対応するissueの内容を整形したツールチップで表示する。表示項目は次のとおり
  - `#番号` とタイトル（長い場合は省略）
  - 状態ラベル（未着手／作業中／判断待ち／レビュー待ち のバッジ。既存の状態バッジの配色を流用）
  - 「実行中」か「待機中（N番目）」かの別
- キーボードフォーカスでも同じツールチップを表示できること
- タッチ端末ではホバーが使えないため、**タップでツールチップを開閉する**表現にしてください（開いている間の見た目、閉じ方も含めて提案をお願いします）
- ツールチップの外観は、既存のポップオーバー・ツールチップ類（あれば）と揃える。ライト／ダーク両テーマで読めること
- キュー部分のクリック・タップは、チップ全体のクリック（そのプロジェクトのissue一覧画面へ遷移）を意図せず発火させないこと。キュー部分のホバー状態・カーソルの表現も、チップ全体のクリック可能な見た目と区別できるようにする（任意: アイコンのクリックで該当issueへ遷移できる見た目にしてもよい）
- issueの情報が取得できない場合（クローズ済み等）は、ツールチップに `#番号` のみを表示する想定のバリエーションも示してください

### 更新後の成果物として欲しいもの

1. 既存のダッシュボードデザインに、上記の変更を反映した更新版
2. プロジェクトチップ内のキューミニ図の各状態: 空／実行中のみ／実行中＋待機少数／実行中＋待機が多く `+N` 省略
3. ツールチップの表示例（実行中・待機中・issue情報なしの3バリエーション）と、タップ時の開閉表現
4. PC幅・モバイル幅それぞれでのチップのレイアウト（キューを入れても崩れないこと）
5. ライトモード・ダークモード両方での見た目

既存デザインとのトーン・配色の一貫性を保ってください。不明点があれば、更新を進める前に質問してください。

## 補足（プロンプト利用者向けメモ）

- この差分プロンプトは [design-prompt-dashboard.md](./design-prompt-dashboard.md) に対する追加変更であり、単独では使わない（最初のダッシュボードデザインが未作成の場合は、まず元のプロンプトを使うこと）。
- 対応する仕様は [issue #233](https://github.com/nosetech/producer-desk/issues/233) を参照。キュー状態の取得元は `DispatchQueue`（[basic-design.md](./basic-design.md) 2-3）で、`GET /api/state` の `project_status[]` にキュー状態（実行中のissue番号・待機中のissue番号リスト・各issueのタイトル／状態ラベル）を載せる想定。
- デザイン更新後は、`CLAUDE.md`「画面デザインの実装ルール」に従い `DesignSync` で `ProducerDesk.dc.html` ＋ `ProducerDesk.logic.js` を取得してから実装する（`truncated` を必ず確認する）。

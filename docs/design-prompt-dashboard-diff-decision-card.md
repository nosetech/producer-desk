## ここからプロンプト

既存のproducer-deskダッシュボードの**判断待ち（needs-human-decision）カード**を変更してください。カード以外の要素のデザイン・レイアウトはそのまま維持してください。

**重要: 既存のマスターファイル（`ProducerDesk.dc.html` / `ProducerDesk.logic.js`）は直接上書きせず、`feature/issue-325-decision-card.dc.html`（と対の`feature/issue-325-decision-card.logic.js`）という新規ファイルとして作成してください。** マスターの`.logic.js`は256KiBに近いため、`.logic.js`はマスターを読み込んで継承し、差分のスタイルだけを定義する形にしてください（`feature/issue-323-snippets.logic.js`と同じ方式）。

### 背景

- 判断待ちカードの「承認」ボタンは運用上一度も使われていません。判断待ちへの対応は常に「返信」で指示を書いています。
- カードの要約は最新コメントを1行にまとめて3行で切っているため、AIの長い最終応答では判断に必要な部分が切れてしまい、毎回「全文を表示」を開いています。
- AIの最終応答には、判断事項を「判断が必要な事項」という見出しの番号付きリスト（各項目の下に選択肢の箇条書きが付くことがある）で書く書式がすでにあり、返信UIの引用領域ではそれを列挙しています（issue #234）。カード上でも同じ情報を使いたいです。

### 変更内容

1. **「承認」ボタンと承認確認ダイアログを削除する**
   - アクション行は「返信」（主ボタン）と「全文を表示」の並びにする。返信ボタンの見た目（主ボタンとして十分目立つか）とボタン幅のバランスを見直してください
   - その下の「レビュー待ちに変更」ボタン、ディスパッチ診断、実行中・失敗時の進捗表示はそのまま維持
   - 「レビュー待ちに変更」の確認ダイアログは残す
   - 判断待ち一覧のサブタイトル「AIからの承認リクエスト」も、承認が無くなることに合わせて見直してください（例:「AIからの判断依頼」）
2. **カード上に判断事項を表示する**（最新コメントに「判断が必要な事項」セクションがある場合）
   - 小見出し「判断が必要な事項」と件数（例:「判断が必要な事項 2件」）
   - 番号付きの判断事項本文。番号は目立たせる。本文中のインラインコード（`` `status:in-review` `` 等）は等幅で表示
   - 選択肢（A案／B案など）をカード上に出すかどうかを決めてください。出す場合は判断事項本文と見分けられる控えめな表示に
   - カードが縦に伸びすぎないよう、カード上に何件・各項目何行まで出し、それを超えた分をどう省略するか（例: 各項目2行で省略、3件目以降は「ほか N件」）を決めてください
   - 判断事項が無い場合（セクションが無い・書式に従っていない）は、従来どおりの「AI」タグ付き3行要約（添付件数表示を含む）を表示する。コメントが0件のカードは従来どおり要約なし
3. **配色**: 判断待ちを示す既存のアクセント色を使い、新しい色は増やさない

### 成果物として欲しいもの

1. 判断待ちカードの次の状態の見本
   - 判断事項あり（1件、選択肢つき）
   - 判断事項あり（4件など省略が発生する件数、長い本文を含む）
   - 判断事項なし（従来のAI要約へのフォールバック）
   - 実行中（進捗表示あり）
2. PC幅・モバイル幅（〜640px、タップ領域36px以上）での見え方
3. ライトモード・ダークモード両方での見た目

既存デザインとのトーン・配色・アイコンの一貫性を保ってください。スタイル値は`.logic.js`側のスタイルオブジェクトとして定義してください。不明点があれば、作成を進める前に質問してください。

## 補足（プロンプト利用者向けメモ）

- この差分プロンプトは [design-prompt-dashboard.md](./design-prompt-dashboard.md) に対する追加変更であり、単独では使わない。
- 判断事項の書式（見出し文言・番号付きリスト・選択肢）は [basic-design.md](./basic-design.md) 3-6の「判断事項セクションの書式仕様」で定義する。

- 作業ブランチ名の新規ファイルとして作成させ、マスターファイル（`ProducerDesk.dc.html`）へのマージは人間がArtifacts上でレビュー・承認した後に行う。

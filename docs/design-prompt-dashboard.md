# Claude Designへの指示プロンプト: producer-desk ダッシュボード画面設計

`producer-desk`（自走型AI開発オーケストレーションシステム）のダッシュボード画面のビジュアルデザインを依頼するためのプロンプトです。以下を丸ごとコピーし、Claude（Artifact機能等）に貼り付けて画面設計を依頼してください。

---

## ここからプロンプト

あなたにはWebダッシュボードのUI/UXデザインをお願いします。まずデザインを検討する前に、これがチャート/データビジュアライゼーションを含む画面であることを踏まえ、`dataviz` スキルの方針（配色・情報密度・アクセシビリティ）に従ってください。可能であれば `artifact-design` の設計原則も踏まえてください。

### 背景・利用者

- システム名: producer-desk（自走型AI開発オーケストレーションシステム）
- 利用者はソフトウェア開発の「プロデューサー」1名のみ。複数のソフトウェア開発プロジェクトをAIエージェント（Claude Code）に自走させ、人間は意思決定・承認のみを行う。
- 主な利用シーンは2つ:
  1. **就寝前後、モバイル端末で同一Wi-Fi/VPN(Tailscale)経由**にダッシュボードを開き、各プロジェクトの状況をざっと確認し、必要なら承認/却下する（暗い部屋・片手操作を想定）。
  2. **PC前で、複数プロジェクトをまとめてじっくりレビュー**する（大きめの画面、マウス/キーボード操作）。
- 外出先からの利用や、通知が来て即座に反応するような使い方の優先度は低い。「気が向いたときに開いて、まとめて確認・判断する」体験を重視する。

### 画面構成

**単一のダッシュボード画面**（レスポンシブ。PC・モバイル両方で同じ画面を使う）。ページ遷移や別画面は不要。

以下の4つの要素を1画面に収める:

1. **判断待ち一覧**（最優先で目立たせる）
   - GitHub issueの一覧。各アイテムに: リポジトリ名、issue番号・タイトル、直近のAIからのコメント要約（1〜2行）、経過時間（例: 「3時間前」）
   - 各アイテムに「承認」「却下」のワンタップ操作ボタンを配置する（誤タップを防ぐため、タップ後に軽い確認、またはUndo可能な設計が望ましい）
   - 却下時は簡単な理由入力ができるとよい（任意項目）
   - 何もない場合は「判断待ちはありません」のような落ち着いた空状態表示

2. ~~**最近の活動ログ（タイムライン）**~~ **（issue #121で廃止）**
   - 複数プロジェクト横断で、直近のコミット・PR作成・issue更新・ラベル遷移（着手/レビュー待ち/完了等）を時系列に並べる
   - 「〇〇プロジェクトが着手しました」「△△プロジェクトでPRが作成されました」のような1行サマリ＋タイムスタンプ
   - 就寝前に「今日1日で何が進んだか」を数秒で把握できる密度にする
   - **廃止の経緯**: 要素4「プロジェクトの並行状況が分かる要素」に状態別件数表示を追加したことで、プロジェクトごとの現在の状態はそちらで把握できるようになり、時系列の活動ログは役割が重複した。孤立したin-progress検知の警告表示・issue単位の返信導線もプロジェクト状況ウィジェット側（チップの最小限の警告インジケータ、issue #116の専用ページ）に移設したため、本要素自体を廃止した（issue #121）。

3. **利用量・リミットモニター**
   - Claude Codeの利用量（サブスクリプションプランのリミットに対する消費率）を表示
   - リミットに近づいている/到達している場合は明確な警告表示（到達時はAgent Runnerが待機中であることも分かるように）
   - 従量課金ではなくサブスクリプションプランのリミット管理である点を踏まえた表現にする（「コスト」ではなく「利用量／リミット」という言葉を使う）

4. **プロジェクトの並行状況が分かる要素**（3〜5プロジェクト程度が同時に動く前提）
   - 各プロジェクトが今どの状態か（未着手/作業中/判断待ち/レビュー待ち）を一目で把握できるようにする（例: プロジェクトごとのステータスバッジ、または上記1〜2の一覧内でリポジトリ名によるグルーピング）
   - **実装後の姿（issue #115, #121）**: 枠で囲ったウィジェットとし、プロジェクト（リポジトリ）ごとのチップに、直近更新issueの状態を示すドット＋リポジトリ名に加えて、状態別のOPEN issue件数（未着手/作業中/判断待ち/レビュー待ち＋タグなし、完了は含めない）を小さなチップの列として表示する。孤立したin-progress検知（旧要素2が担っていた警告表示）は、対象プロジェクトのチップにリポジトリ名の隣の▲警告アイコンとして最小限のインジケータを表示する形で統合した。詳細（どのissueが該当するか）はプロジェクト単位のissue一覧を表示する専用ページ（issue #116）に譲る。

5. **新しい指示を出す入力欄**
   - 自由記述のテキストボックスで、AIエージェントに新しい指示を出せるようにする。用途は2つ:
     a. **既存issueへの追加指示**: 一覧（判断待ち一覧・活動ログ）の各アイテムから「返信する」を選ぶと、そのissueに向けたテキスト入力ができる。issueの状態を問わず送信可能（作業中のプロジェクトに割り込んで指示することも想定）。承認・却下ボタンは、この自由記述欄に定型文があらかじめ入った状態、という位置づけで統一感のあるUIにしてほしい。
     b. **新規タスクの作成**: 対象プロジェクトを選び、タイトルと指示内容（プロンプト）を入力して新しいタスクを作る。作成時に「今すぐ着手」「あとで着手（todo登録のみ）」を選べるトグル/ボタンを用意する。
   - 常時画面下部やフローティングボタンなど、常にアクセスしやすい位置に配置してほしい（就寝前に「あの件、明日はこう進めて」とさっと打ち込めるイメージ）。
   - 実行中のプロジェクトへ指示を送った場合は、「現在実行中のため、完了後に指示が反映されます」のような状態が伝わる表示があるとよい。

### インタラクション・技術要件

- フロントエンドはNext.js（React）で実装する前提。コンポーネント分割を意識した設計を歓迎する。
- レスポンシブ: スマートフォン（375px〜）と、PCの広い画面（1280px〜）の両方で自然に使える1つのレイアウトにする（別レイアウトを2つ作るのではなく、CSSのブレークポイントで調整する設計が望ましい）。
- 承認/却下のワンタップ操作は、モバイルでの誤操作防止と、PCでの素早い連続処理のしやすさを両立させたい。
- ライトモード・ダークモード両方に対応してほしい（就寝前の利用が多いため、ダークモードの見やすさを特に重視）。
- 個人の運用ツールであり、ブランドカラー等の制約はない。配色は `dataviz` スキルのパレットに従い、状態（判断待ち/作業中/レビュー待ち/完了/警告）が色で直感的に区別できるようにしてほしい。

### 成果物として欲しいもの

1. ダッシュボード全体のビジュアルデザイン（HTML/CSSのArtifactとして、ダミーデータを使った動作するモックアップ）
2. モバイル幅・PC幅それぞれの見え方が分かるようにしてほしい（レスポンシブ確認）
3. 判断待ちアイテムの承認/却下操作のインタラクション（クリック時の見た目の変化）を含めてほしい
4. 自由記述の指示入力欄（既存issueへの返信・新規タスク作成の両方）のインタラクションを含めてほしい
5. ライトモード・ダークモード両方の見た目

不明点があれば、デザインを進める前に質問してください。

## 補足（プロンプト利用者向けメモ）

- 本プロンプトが参照しているデータ項目・API仕様は [basic-design.md 2章](./basic-design.md#2-オーケストレータダッシュボードapi設計) に対応している。デザイン確定後、実装時にこの対応関係を確認すること。
- 状態バッジの色分けは [basic-design.md 1章](./basic-design.md#1-データモデル状態遷移設計) のラベルスキーマ（`status:todo` / `status:in-progress` / `needs-human-decision` / `status:in-review`）に対応させる。
- デザイン成果物（Artifact）ができたら、URLまたはコードをこのリポジトリの実装issueに添付し、Next.js実装のベースとする。
- 本プロンプトでの初回デザイン後に指示入力欄の要件が追加された場合は、ゼロから作り直すのではなく [design-prompt-dashboard-diff.md](./design-prompt-dashboard-diff.md) の差分プロンプトを使って既存デザインを更新すること。
- 「プロジェクトの並行状況が分かる要素」（要素4）に状態別件数を追加し、「最近の活動ログ（タイムライン）」（要素2）を廃止する変更は [design-prompt-dashboard-diff-status-counts.md](./design-prompt-dashboard-diff-status-counts.md) の差分プロンプトを使うこと（issue #115）。
